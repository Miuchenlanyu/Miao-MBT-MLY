一、项目定位
----------------------------------------------------------------
Miao-MBT-MLY 是一个「纯图库仓库」+ 一个读取它的 Yunzai 插件：
  - 仓库（本仓库）：只存放面板图资源，不含逻辑。
  - 插件 Miao-MBT-MLY-Plugin：运行时从本地图库（优先）或 GitHub（回退）调取并发图。

二、目录结构（仓库根）
----------------------------------------------------------------
Miao-MBT-MLY/
├── genshin/                  # 原神面板图 —— 插件实际读取的分区
│   └── R
│       └── normal-character
│           └── <角色名>
│               ├── <角色名>_01.webp
│               └── <角色名>_02.webp
├── starrail/                 # 崩坏：星穹铁道
│   └── R/...
├── zzz/                      # 绝区零
│   └── R/...
├── tools/
│   └── build_index.mjs        # 扫描各分区生成 index.json
├── index.json                # 清单（由 build_index.mjs 生成，供 GitHub 回退解析）
├── README.md                 # 使用说明（含本地优先 + 安全提醒）
├── 地址.txt                  # 托管仓库地址
└── 仓库目录结构.txt           # 本开发文档

说明：
  - 游戏分区文件夹名固定为 genshin / starrail / zzz，与插件 GAME_ALIAS 对应。
  - 分级文件夹 R / R17 / R18 放在游戏分区下，其下 normal-character/<角色名>/ 放图。
  - 角色名 = normal-character 下的文件夹名（主），或文件名方括号 [角色名]（辅）；两者都可作为指令关键词。
  - 文件名任意（如 <角色名>_NN.webp 或 [角色名] id.jpg 均可），序号从 01 起。
  - 图片格式支持 webp / png / jpg / jpeg / gif；推荐 webp。
  - 每个分区目录内含 .gitkeep，确保空目录也能进 git。
  - 令牌.txt 含 GitHub PAT，已被删除，切勿再以明文落盘（见安全提醒）。

三、插件现状（已完成）
----------------------------------------------------------------
文件：plugins/Miao-MBT-MLY-Plugin/apps/mbtPanel.js
  - 本地优先：直接读本地 Miao-MBT-MLY/<游戏>/<分级>/normal-character/<角色名>/ 发图，不联网、不卡死。
  - GitHub 回退：本地缺失时走 jsDelivr 直链（开发完成后从 GitHub 取图）。
  - 全程超时：远程请求 8s AbortSignal.timeout，失败即返回，绝不挂起。
  - 路由抢占：priority=1，高于 miao-plugin（默认 500），确保 #MLY面板* 由本插件接管，
    不会被 miao 的「消息含面板即接管」规则抢走后去查外部 API 卡死。
  - 指令：#MLY面板 <游戏> <角色> [序号|all]、#MLY面板列表、#MLY面板更新、#MLY面板（帮助）。
  - 图库侧 tools/build_index.mjs：数字序排序、含 gif、跳过非角色目录，生成与插件一致的 index.json。

四、关于 R / R17 / R18 过滤（设计决策）
----------------------------------------------------------------
经确认，本期不做分级过滤，决策如下：
  1) 分级粒度：掠过。MLY 插件不实现 R17/R18 权限闸门，直接沿用 miao 插件自身的随机/既有权限逻辑。
  2) 分级目录用途：R / R17 / R18 文件夹仅放在各游戏分区下做仓库内分类（如 genshin/R/normal-character/...），
     是给维护者管理用的，插件运行时不按分级过滤、不读取该层级做权限判断。
  3) 图库内容定位：R 级（全年龄）。库内只放 R 级面板图，无需在插件侧做分级展示控制。
=> 结论：过滤相关的代码复杂度与安全风险（R18 泄露）本期全部规避，插件保持简单。

五、开发难度评估
----------------------------------------------------------------
整体难度：低（发图管线已完成，剩余为内容填充与人工归类，无复杂逻辑/外部服务/安全闸门）。
  已完成（低）：
    - 插件发图：本地优先 + GitHub 回退 + 超时 + 路由抢占，纯文件读写 + 正则路由。
    - 图库骨架：三个游戏分区 + build_index + README + 本文档。
  待做（低～中）：
    - 往 genshin/starrail/zzz 放图，跑 node tools/build_index.mjs 生成 index.json 并 push。
    - 本地图库直接可用（无需 push），把图片丢进本地目录即可离线发图。
    - 人工把角色按 R/R17/R18 归类进 游戏名/（非代码工作）。
  风险点：
    - 唯一风险是 GitHub PAT 明文落盘（已删除，后续用 GH_TOKEN 环境变量或本地凭据）。
    - 远程拉取依赖 jsDelivr 可达性；本环境网络受限，故主推「本地图库优先」。
